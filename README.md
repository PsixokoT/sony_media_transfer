# sony_media_transfer

Приложение для Windows 11, которое копирует фото и видео с Sony A7 IV (прошивка 6.01) на компьютер. Сейчас переписывается с консольной утилиты на Tauri.

## Спецификация

### Стек

- Tauri 2. Логика на Rust (`src-tauri/`), интерфейс на TypeScript + React + Vite (`src/`).
- Rust stable и Node 24 закреплены в `mise.toml`. MSVC Build Tools (C++ и Windows SDK) ставятся через winget.
- Результат сборки — portable exe, без установщика и автообновлений.
- Только Windows 11.

### Откуда берём файлы

- Камера работает в режиме MassStorage (MSC): `MENU → Setup → USB → USB Connection Mode → MassStorage(MSC)`, `USB LUN Setting` = Multi. MTP (показывает только слот 1 и работает медленно) и Camera Remote SDK не используем.
- Картой камеры считается съёмный диск, на котором есть `DCIM\NNNxxxxx`, `M4ROOT` (CFexpress Type A, так на текущей карте) или `PRIVATE\M4ROOT` (SD). Диск PMHOME (внутренняя память камеры, там папка LICENSE) и пустые слоты пропускаются. Картридер и флешка с такой же структурой распознаются так же.
- Отдельного режима отладки нет. Логика проверяется юнит-тестами на временных папках, вживую — флешкой со структурой карты.
- Подключение и отключение камеры отслеживаются автоматически: раз в 2 с приложение проверяет, какие съёмные диски — карты (только папки, файлы не читаются). Файлы перечитываются, только когда набор карт меняется.

### Файлы и группировка

- Фото: ARW на слоте 1, JPG или HEIF (`.HIF`) на слоте 2. Видео XAVC HS: `M4ROOT\CLIP\C0001.MP4` + `C0001M01.XML`, прокси `M4ROOT\SUB\C0001S03.MP4`. На SD-карте перед `M4ROOT` есть ещё `PRIVATE\`. `MEDIAPRO.XML` — служебный файл, его не копируем.
- Файлы со всех карт показываются одним списком по дням. День — это дата съёмки: у фото EXIF `DateTimeOriginal`, у видео `CreationDate` из XML. Если метаданных нет, берётся дата файла. Граница дня — полночь.
- Одна плитка — один кадр или клип. ARW, JPG и HIF связываются по имени и дате съёмки, MP4, XML и прокси — по номеру клипа. Если на двух картах лежат одинаковые файлы, копируется один.
- Не проверено: совпадают ли номера ARW и JPG на двух картах (второй карты пока нет). Если не совпадут, файлы просто покажутся отдельными плитками.

### Просмотр и отбор

- Превью фото — JPEG, встроенный в ARW (у JPG — миниатюра 160×120 из EXIF). В полноэкранном просмотре JPG показывается целиком. У HIF превью есть, только если в нём есть JPEG-элемент: HEVC WebView не показывает. На камере это не проверено. Есть кнопка «Открыть во внешней программе».
- Видео: сначала играем исходник в WebView2. Если не играет — прокси, если прокси нет — кнопка «Открыть в системном плеере». «Не играет» — это ошибка или видео без картинки: если декодера нет, Chromium играет только звук. Видео отдаётся через asset-протокол Tauri, ему открыт только `M4ROOT`.
- На этом ПК WebView2 (Edge 142) играет HEVC Main и Main 10, но не 4:2:2: тестовый клип H.265 4:2:2 10 бит переключается на прокси. Звук камеры (PCM `twos`) играет.
- Клавиатура: Enter открывает просмотр, ← / → листают, Пробел ставит или снимает галочку, Esc закрывает. ← / → двигают курсор и в сетке.
- Выделение как в Lightroom и Проводнике: щелчок выделяет плитку, Ctrl+щелчок добавляет или убирает её, Shift+щелчок и Shift+← / → выделяют диапазон, Ctrl+A — всё. Двойной щелчок открывает просмотр. Пробел и галочка на выделенной плитке ставят или снимают галочки у всего выделения; если в выделении есть и отмеченные, и неотмеченные, Пробел отмечает все.
- Перед открытием видео во внешней программе плеер в приложении ставится на паузу.

### Уже скопированное

- При каждом запуске корень назначения обходится в фоне. Учитываются только медиафайлы, `.xmp` и `.acr` пропускаются. Индекс-файла нет: ~25 тыс. файлов обходятся примерно за 2 с.
- Совпадение определяется по имени, размеру и дате съёмки. Дата нужна, потому что номера `DSC…` после 9999 начинаются заново. Дату даёт диапазон в имени папки верхнего уровня; файл открывается (EXIF, XML клипа) только если день в диапазон не попал: чтение с HDD стоит ~12 мс на файл. Уже скопированное показывается серым и без галочки. Если отметить его вручную, оно копируется снова.

### Копирование

- Копируются отмеченные плитки, с прогрессом. С карты ничего не удаляется.
- Два режима: одна папка на весь диапазон `ГГГГ.ММ.ДД - ГГГГ.ММ.ДД - описание` или папка на каждый день `ГГГГ.ММ.ДД - описание`. Внутри папки все файлы лежат вместе, как в старой утилите.
- Если день попадает в диапазон уже существующей папки библиотеки, эта папка предлагается по умолчанию, остальные дни идут в новую папку. Диапазон определяется по дате в начале имени; старые имена без « - » перед описанием тоже распознаются.
- Файл сначала пишется как `*.part`, затем переименовывается, после чего сверяется размер. Дата файла сохраняется. Главное — скорость, поэтому файлы идут по одному и без fsync. Библиотека не перезаписывается: файл с тем же именем и размером пропускается, с другим размером — копирование останавливается с ошибкой.

### Прочее

- Корень назначения задаётся в окне «Настройки»: вписывается или выбирается стандартным диалогом выбора папки. Сохраняется. Сейчас это `e:\FOTO\Sony A7IV\PHOTOS`.
- Языки: русский и английский, по умолчанию — язык Windows, переключаются в настройках. Свои сообщения об ошибках Rust пишет на выбранном языке, системные приходят на языке Windows.
- Кнопка «Извлечь» безопасно извлекает USB-устройство каждой карты, как «Извлечь» в Проводнике. Поэтому уходят все диски камеры (оба слота и PMHOME), а у картридера — все его слоты. Если диск занят другой программой, показывается ошибка. Сама после копирования камера не извлекается.

## Разработка

```sh
mise install                # Rust и Node из mise.toml
npm install
npm run tauri dev           # запуск с горячей перезагрузкой
npm test                    # юнит-тесты Rust
npm run tauri build         # src-tauri\target\release\sony-transfer.exe
```
